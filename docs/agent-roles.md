# エージェントの役割

この文書は Klein のエージェントを会話との関係で分類し、どの役割に何を許すかを決めるための基準を説明する。読者はエージェントを追加する開発者と、表と裏のやり取りを設計する開発者を想定する。個々の実装の説明ではなく、役割の境界と、境界を破らないための仕組みを書く。

## 3 つの役割

Klein のエージェントは、会話に属するかどうかと、会話の surface を書けるかどうかで 3 つに分かれる。

- 会話エージェントは 1 つの会話に属し、その会話の surface を書く唯一の存在である。
- 会話付随エージェントは 1 つの会話に属するが、surface は書かない。結果を会話エージェントへ返す。
- 独立エージェントはどの会話にも属さない。呼び出し元のために走り、結果を呼び出し元へ返すか、ストアを変更する。

surface とは Discord のチャンネルに表示される発話を指す。テキストメッセージ、読み上げ、音声のいずれも surface への書き込みとして扱う。

| 役割     | 会話への所属 | surface  | セッションの寿命 | assistant text の行き先 |
| -------- | ------------ | -------- | ---------------- | ----------------------- |
| 会話     | する         | 書ける   | 会話と同じ       | surface に出さない      |
| 会話付随 | する         | 書けない | タスクと同じ     | 会話エージェントへ返す  |
| 独立     | しない       | 書けない | 呼び出しごと     | 呼び出し元へ返す        |

## assistant text の扱い

会話エージェントの assistant text は発話ではない。発話は `discord_send` などの surface ツールを呼んだ結果としてだけ生まれる。ターンがツールを呼ばずに終われば、そのターンは何も言わなかったことになる。`normalizeCompletedAssistantText` はこの規則を次のターンの文脈に反映する。

会話付随エージェントの assistant text も発話ではない。会話エージェントへの返り値であり、会話エージェントが読むデータになる。会話付随エージェントは surface ツールを持たないので、返り値を発話に変える経路がない。

独立エージェントの assistant text は呼び出し元が解釈する。メモリ処理のように JSON として parse する場合も、ユーザーメモリ更新のようにファイルの変更だけが意味を持つ場合もある。

## 境界を保つ仕組み

`AgentRole` は役割を型で表し、`resolveAgentPolicy` が役割ごとの surface の所有、寿命、assistant text の行き先を返す。`assertSurfaceToolsAllowed` は surface ツールを持つことを許されない役割に surface ツールが渡された時点で失敗する。

surface ツールは `discord_send`、`discord_speak`、`discord_voice` の 3 つである。会話エージェントだけがこれらを持てる。

## 現在の割り当て

- `DiscordAgent` は会話エージェントである。テキストチャンネルとボイスチャンネルの両方で使う。
- `AttachedAgentCoordinator` のタスクは会話付随エージェントである。会話エージェントと同じリッチな Pi セッションを使い、surface ツールと rotation を持たない。会話エージェントが `attached_start` で始め、`attached_send` で続きの指示を渡す。結果は `attached.result` イベントとして会話へ戻る。
- `PiStandaloneSessionRunner` のセッションは独立エージェントである。ユーザーメモリ更新がこれを使う。
- `PiMemoryProcessor` の完了呼び出しは独立エージェントである。ツールを持たず、結果を呼び出し元が parse する。

## 会話付随エージェントのやり取り

会話エージェントは `attached_start` でタスクを始める。タスクは会話エージェントと同じファクトリから作られ、拡張、スキル、MCP、権限、画像解析、background compaction を持つ。surface ツールは持たず、rotation にも参加しない。セッションは `sessions/attached/` に置かれ、トレースは `role: attached` で記録される。`attached_send` は同じセッションへ続きの指示を渡し、`attached_close` はセッションを捨てる。`attached_list` はその会話のタスクを返す。

タスクが 1 回のプロンプトを終えると、結果は `attached.result` イベントとして会話へ届く。イベントの本文は外部データとして扱うよう注記され、会話エージェントが発話するかどうかを決める。タスクは Discord に直接書かない。

タスクの状態はプロセス内にだけ保持する。再起動すると、実行中だったタスクも待機中だったタスクも失われる。セッションのファイルは `sessions/attached/` に残るが、タスクとの対応は復元しない。Web UI のセッション一覧にも出ない。

## 役割を選ぶ基準

用途ではなく、結果を会話の時間軸に置く必要があるかで選ぶ。

メモリ更新は会話のどの時点で起きてもよい。結果はストアに残り、次のターンの文脈として読まれる。だから独立エージェントで足りる。

調査のように、結果をどのメッセージへの返答として出すかが会話の進行に依存する仕事は、会話付随エージェントにする。会話付随エージェントは結果を会話エージェントへ返し、発話するかどうかは会話エージェントが決める。
